## 🟡 Issues & Concerns

### Critical Issues

- [ ] **1. Security: `math.evaluate()` usage** (core.ts:79)
  - While mathjs claims to be "safe", you're evaluating arbitrary user input
  - README mentions sandboxing intentions but it's not implemented
  - **Recommendation**: Document this clearly, consider iframe sandboxing for untrusted documents

- [ ] **2. Non-null assertions everywhere** (parse.ts:44, 82, 86, 96, etc.)
  ```typescript
  BODY_REGEX.exec(body)!.groups! as Record<string, string | undefined>
  ```
  - Disabled the rule in eslint but using `!` extensively anyway
  - **Risk**: Runtime errors if regex doesn't match
  - **Fix**: Add proper null checks or validation

- [ ] **3. Hardcoded `EUR` currency** (main.ts:29)
  ```typescript
  math.createUnit("EUR")
  ```
  - No other currencies supported
  - Inconsistent with the plugin's flexible design
  - **Fix**: Make currencies configurable or add common ones

### Code Quality Issues

- [ ] **4. Missing error handling in `markdownPostProcessor`** (main.ts:63-95)
  - No try-catch around `LMathBlock.init` or DOM manipulation
  - Errors would crash the entire post-processor
  - **Fix**: Wrap in try-catch, log errors gracefully

- [ ] **5. Sketchy timeout loop** (main.ts:68-72)
  ```typescript
  let guard = 1000
  while (guard-- > 0 && !el.closest('.markdown-preview-view')) {
    await new Promise(resolve => window.setTimeout(resolve, 1))
  }
  ```
  - Polling with sleep is fragile
  - **Fix**: Use proper event listeners or MutationObserver

- [ ] **6. Global mutable state** (editExtension.ts:41, 58)
  ```typescript
  let mouseButtonIsDown = false
  const lmBlockOffsets: {...}[] = []
  ```
  - Multiple editor instances would share this state
  - **Fix**: Move to plugin instance or view plugin state

- [ ] **7. Inconsistent error checking** (core.ts:67-72)
  ```typescript
  if (!parseResult.ok)
    if (parseResult.error instanceof ResultParseError) {
      return createErrorBlock(parseResult.error.message)
    } else {
    throw parseResult.error
  }
  ```
  - Missing braces, inconsistent indentation
  - **Fix**: Add braces, format properly

- [ ] **8. Type assertion casting** (parse.ts:44-45)
  ```typescript
  BODY_REGEX.exec(body)!.groups! as Record<string, string | undefined> as BodyRegexGroups
  ```
  - Double type assertion indicates type system fighting
  - **Fix**: Create proper type guards or stricter regex types

### Design Issues

- [ ] **9. Attribute misuse in reading mode** (main.ts:78-81)

  }
  doc.setAttribute("x--data-lmath-ran", "1")

  - Sets attribute but doesn't return early
  - Attribute name has weird prefix `x--`
